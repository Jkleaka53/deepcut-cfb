# Slice 4: Run Phase Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every matchup page gets a "Running game" section (each offense's run game vs. the other team's run defense, ranked nationally, with an edge call), and the run rows join Biggest edges, the edge card, Key badges and the home Edge chip.

**Architecture:** The engine adds per-team-game rushing aggregates from the play-by-play it already caches (garbage time and FCS games filtered exactly like the pass stats). They flow through the existing season profile, early-season blend and percentile ranks, and `units.py` gains a second table set written to `section.runUnits`. The web renders them with the existing HeadToHead rows under a new tab.

**Tech Stack:** Python (uv, pandas, pytest), Next.js 15 static export, React 19, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-cfb-matchups-design.md` "Unit vs. unit" → "Run phase (second, same pattern): line yards, stuff rate, power success, second-level and open-field yards, rushing EPA." Owner skipped questions (2026-11-10); *(my call)* marks executor decisions.

## Global Constraints

- Edges in words only (Even / Slight edge / Big edge). Never win %, predicted score, margin or odds.
- Stats strictly before kickoff; garbage time excluded; FBS-vs-FBS games only (same as the pass phase).
- No animations; square corners; light default + dark; tokens only.
- No new CFBD calls: play-by-play is already cached (`yardsGained`, `yardsToGoal`, `down`, `distance` are in it).

## My calls (record in spec at the end)

- Runs = playType in `config.PLAY_TYPES["rush"]` ("Rush", "Rushing Touchdown"). QB scrambles count as runs (CFBD can't tell them apart); sacks never do.
- Per run, with y = yardsGained:
  - line yards = 1.2·y if y < 0; else min(y, 4) + 0.5·min(max(y − 4, 0), 6) (Football Outsiders rule; max 7 per carry).
  - second-level yards = min(max(y − 5, 0), 5); open-field yards = max(y − 10, 0). Both averaged over all runs.
  - stuffed = y ≤ 0.
  - power chance = (down in 3, 4 and distance ≤ 2) or yardsToGoal ≤ 2; converted = y ≥ distance (or a TD).
  - rushing EPA = mean ppa over runs with ppa.
- Metrics (offense / defense allowed; direction): `rush_epa` (+1 / −1), `line_yards` (+1 / −1), `stuff_rate` (−1 / +1), `power_success` (+1 / −1), `second_level` (+1 / −1), `open_field` (+1 / −1).
- Two tables, offense label first: "Run blocking vs. run defense front": Yards the line creates, Runs stuffed, Short-yardage runs converted. "Running game vs. run defense": Points added per run, Yards past the line (5 to 10), Breakaway yards (past 10).
- `runUnits`, `runEdge`, `runBiggestGap` are new section keys; `units`/`edge`/`biggestGap` stay passing-only, so GOTW and QB tiers are unchanged.
- Swing Key badges extend to run rows: `rush_ppa`→`rush_epa`, `stuff`→`stuff_rate`, `line_yards`→`line_yards`.
- Home Edge chip (`summary_gap`) and Biggest edges consider run rows too; context line reads "When X runs".
- Edge card adds one line per side: "Georgia runs → Missouri D · Slight edge". Footnote: "The lines below are the passing and running stats."
- Tab order: Preview, Passing game, Running game, QB splits, Availability. Running game tab only when `runUnits` exists (old JSON).

## Review Focus

1. Team with zero runs before a game (week 1 / FCS-only priors): run cells null, no edge, no crash.
2. Power chances = 0 for a team: power_success is NaN → null cell, not 0%.
3. Old matchup JSON without `runUnits`: Running game tab hidden; Preview/Edge card unchanged.
4. A Key driver on a run stat badges the run row, not a pass row with the same position.
5. Early-season blend: run columns blend with last season like pass columns (not left this-season only).
