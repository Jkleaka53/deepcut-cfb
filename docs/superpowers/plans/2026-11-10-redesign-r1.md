# DeepCut CFB Redesign R1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the approved sports-app redesign (team colors, logos, scoreboard home, head-to-head matchup page), plus kickoff weather, a Top 25 filter, and the QB-availability card, behind a Vercel preview the owner approves before it goes live.

**Architecture:** The Python engine gains additive JSON fields (team info, AP ranks, venue, weather, per-side edge, biggest gap, availability) so the live site on `main` keeps working while the branch is reviewed. The Next.js static site is restyled around tokens and new components; logos are downloaded by a Node prebuild step on Vercel and never committed.

**Tech Stack:** Python ≥3.12 (uv, pandas, requests, pytest, responses), Next.js 15.5 static export, React 19, TypeScript, Vitest (jsdom), `next/font/google`, `lucide-react`, Open-Meteo, GitHub Actions, Vercel.

**Spec:** `docs/superpowers/specs/2026-11-10-redesign-design.md` (builds on `docs/superpowers/specs/2026-11-10-cfb-matchups-design.md`). R2 (Availability what-if) in the same spec is NOT part of this plan.

## Global Constraints

- Work on branch `redesign` (exists, tracks `origin/main`; set its upstream to `origin/redesign` on first push). Never merge to `main` until the owner says the preview is done.
- **Asking first:** pushing the branch (creates a public branch + Vercel preview) and merging are outward-facing: ask the owner before each.
- **Never** read, print or commit `.env`. The CFBD key stays in `.env` / the `CFBD_API_KEY` secret.
- **No animation anywhere:** no CSS transitions or animations, no `scroll-behavior: smooth`, no motion libraries. Simply never author any (no blanket override rule needed).
- **Square corners everywhere:** `border-radius: 0` on all app UI.
- Indicator color tokens (exact): light `--accent:#1f6feb; --accent-tint:#e8f0fe; --accent-text:#1a5fd0; --on-accent:#fff`; dark `--accent:#4c8dff; --accent-tint:#0f2142; --accent-text:#7eaaff; --on-accent:#fff`.
- Theme tokens (exact): light `--bg:#f2f3f5; --card:#ffffff; --ink:#0b1220; --muted:#5f6b7c; --line:#dfe3e8; --chip:#e9ecf0`; dark `--bg:#090b0e; --card:#13171c; --ink:#f3f5f7; --muted:#8e9aab; --line:#252b33; --chip:#1c2128`.
- Fonts: Barlow Condensed (600, 700, 800; 900 italic for the logo) for names, headlines, tabs, chips, numbers; Inter for reading text. Self-hosted via `next/font/google`.
- Theme defaults to **light** regardless of OS; choice stored in localStorage key `cfbm:theme`, every access in try/catch.
- Copy: disclaimer text unchanged (`DISCLAIMER` in `engine/cfbm/config.py` and `web/components/Disclaimer.tsx`); footer adds "Not affiliated with any team, conference or the NCAA." and "Data: CollegeFootballData.com · Weather: Open-Meteo".
- Edge words: Clear band → "big edge", Slight → "slight edge", under 15 → "Even". Never odds, percentages-as-chances, "50/50", scores or margins.
- New JSON fields are **optional** in `web/lib/types.ts` and every component renders when they are absent (old data during merge).
- Generated data in `web/public/data` committed on the branch is for the preview only; at merge time `main`'s copy wins and the refresh workflow is dispatched (Task 13).
- No horizontal page scroll at 375px wide in either theme.
- Engine logic is test-first (pytest); web logic lives in `web/lib/*.ts` and is test-first (vitest). Components stay thin.

## Review Focus

1. **Team colors that fail contrast** (WVU gold, Missouri gold, Tennessee orange as fills behind white text; Michigan/Navy navy as text in dark mode) → the contrast rule picks alt or adjusts; covered in Task 1 tests with real hex values.
2. **Games with missing data** (FCS opponent, TBA kickoff, no venue coordinates, dome, completed, kickoff > 16 days) → weather block degrades to the right status, page still renders; Task 3 tests.
3. **Old-format JSON** reaching the new UI (merge window) → no crash, sections without new fields hide; Task 8 test on `normalizeMatchup`.
4. **Postseason and week 1 ranks** (CFBD numbers every bowl week 1; preseason poll) → rank rule from spec; Task 2 tests.
5. **A QB with no prior primary-passer games** (week 1, new starter) → availability shows no false warning; Task 5 tests.

**Interfaces:**

Rules (spec): look only at this season's games before `before_order`.
- No primary-passer game yet → `[]` (no claim).

`AVAILABILITY_REPORTS` holds SEC, Big Ten, ACC, Big 12 with `when = "Posts Wednesday, updated until about 90 minutes before kickoff."`. **Verify each URL loads (HTTP 200, page mentions availability) before committing; leave out any conference whose page can't be confirmed.** Teams in other conferences get `url: None` and the UI shows the spec's "No official availability report for this game."
